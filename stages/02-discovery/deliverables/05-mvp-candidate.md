# Pilot 候选范围、指标与 Non-goals

## 候选工作流

邮件 → WorkItem → 字段提取与单位规范化 → 关键缺口检查 → 客户历史候选 → 受控产品候选与依据 → 技术升级建议 → 销售复核 → 回复草稿。Stage 3 将检查数据是否支撑每一步；不因本图存在就确定实施全部模块。

## Automation Ladder

| 层级 | 候选动作 | 当前边界 |
|---|---|---|
| 1 | 收件确认 | 可作为低风险候选，需确认邮件系统和客户体验；本阶段不接入 |
| 2 | 补问草稿 | 可生成，销售审核措辞与缺口 |
| 3 | 产品候选与解释 | 需要权威数据、规则和工程师/销售复核 |
| 4 | 正式报价与发送 | V1 不自动执行 |

## 成功指标候选

业务：复杂询盘从收到到首次有意义回复的时间；流程：按复杂度分组的升级率、工程师每工作日咨询事件；产品：销售使用工具后的任务主动时长及复核时长；AI：关键字段准确率、缺失关键信息召回率、Top-3 候选覆盖率、关键规则违规数。定义和初步门槛将在 Stage 3 Golden Dataset 中记录，不能用 Stage 1 定向样本的 50% 升级率作真实基线。

## Non-goals V1

自动最终选型、自动正式报价、未经复核自动发送技术结论、替代工程师、首版覆盖全部产品线。价格与敏感折扣不进入首版生成模型上下文。
