# Pilot 计划与人工工作流

## 范围和阶段门

演练按 2026-09-21 至 2026-10-02 的 10 个工作日设计，每天 Linda、Mike、Anna 各 6 条合成活动，陈工承担技术复核。只模拟英文标准离心泵询盘和已有批准知识。高温、化工/ATEX、非离心泵进 Shadow；非标准技术条件需工程师。所有推荐与草稿都经销售复核；高风险先经工程师。没有自动报价、发送、真实用户、真实邮箱或客户系统接入。

| 阶段 | 必需证据 | 本仓库状态 |
|---|---|---|
| Offline Eval | 合成回归、失败分类、数据契约 | 可演练；Stage 4 字段门槛仍有缺口 |
| Shadow | 隐藏结果与人工标签，不能流入销售可见队列 | 可演练 3 例；无现场标签 |
| Internal Review | 真实账号、角色授权、审核责任与审计 | 仅本机角色模拟 |
| Limited Pilot | 真实授权来源、冻结前测、值班/回退、告知试点用户 | `NOT_EVALUATED` |
| Broader Pilot / Automation | 风险、价值、成本和合规证据 | 未进入 |

原稿的发布决定是叙事情节，不是本仓库的签核。要进行真实有限试点，先收集来源授权及治理签核、生产级 SSO/RBAC、真实工作流入口、可观测性与告警、数据/代码双发布门、业务前测和事故值班责任；逐项由业务与安全负责人审批。

## 角色与路径

```text
标准询盘 → 抽取/客户上下文/推荐/知识/草稿 → 销售审核 → 人工使用结果
                                         ↘ 高风险 → 陈工技术任务 → 销售任务
范围外询盘 → Shadow 隔离 → 离线分析；不进入销售队列
依赖不可用 → 标记缺口/回退 → 人工确认；禁止静默补值
```

Linda（资深）默认只需候选、警告、草稿；Mike（新人）默认展开规则/来源；Anna（中级）可按需展开；陈工看技术问题、候选、缺口、规则和来源。页面上的 `admin` 只可浏览模拟任务，不能代替负责人批准。销售只能处理分派给自己的任务；工程师只能处理分派给自己的技术任务。`approve` 仅代表本地教学审核事件，不会发送内容。修改、拒绝、升级、覆盖要写原因；工程师覆盖还要选 `commercial_preference`、`missing_rule`、`bad_ranking`、`data_error` 或 `user_preference`，为周复盘保留可分类反馈。

工作流摩擦要按角色观察：任务何时触发、从邮箱跳到工具几次、查证据要几步、审核是否打断工作、升级后的等待由谁承担。脚本中的 `manual_copy_v1` 与第二周切换次数下降只是反事实练习。若要验证 Inbox 集成是否带来变化，须在真实试点冻结人群和口径，记录任务复杂度和采用前后条件，不能把合成周差当作因果效应。

## 演练日程与责任

| 时间 | 行动 | 留下的证据 |
|---|---|---|
| 上线前 | 冻结范围、人员、前测口径、批准来源；演练坏数据和依赖故障 | 范围表、真实基线、发布/回退记录 |
| 每日 | 记录符合范围的全部询盘、是否尝试/完成辅助、任务完成与放弃、系统错误 | 原始事件与脱敏 Trace |
| 第 1 周末 | 按角色×复杂度检查采用与修改原因，观察工作流摩擦 | 周复盘和一项优先改动 |
| 第 2 周末 | 复测同口径，复查风险、成本、专家负担和覆盖原因 | Stop / Iterate / Expand / Productize 决策记录 |

本仓库只能执行合成日程；[前测假设](../data/baseline.json)不等于现场测量。真实业务时间必须从收件至首次响应、销售主动处理开始/结束、工程师咨询请求/答复分别采集，同一询盘按稳定 ID 去重。
