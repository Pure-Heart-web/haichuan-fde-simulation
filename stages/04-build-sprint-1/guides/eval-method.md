# 评估口径与回归 CI

评估文件 [`inquiry_eval_v0.jsonl`](../data/inquiry_eval_v0.jsonl) 有 100 个全合成案例：50 条常规/中英混合、20 条单位变体、15 条缺字段、10 条 HTML、5 条附件占位。样本是从独立模板生成的回归练习材料，不是从真实销售邮件随机抽样；附件只标记存在，不读取内容。

每例标注九个字段，包括期望为 `null` 的字段。准确率 = 值正确的字段比较数 / 该字段全部案例数；数值容差为 0.03 个 canonical 单位。报告另列非空准确率与空值准确率，避免大量空值掩盖漏提。关键字段门槛按**每个字段**≥95%，解析失败率 <2%，已知关键 Schema 违规数为 0，失败抽取 100% 入人工审核队列；真实试点还需审核率和回归阈值。

`stage4.py eval --check-baseline` 将结果与 [`regression-baseline.json`](../data/regression-baseline.json) 比较：整体或任一字段下降超过 1 个百分点，或解析失败率上升，则以退出码 4 失败。Baseline 是当前离线正则实现对合成集的实测值，仅用于发现回归；它低于某些 Pilot 门槛，CI 通过不代表 Release Gate 通过。

目前 P95 是本机正则处理耗时，不是 API 模型延迟；外部模型成本为 0，因为没有调用模型。正式模型接入后必须另采 API latency、tokens、费用、超时率和数据安全事件。真实样本评估应冻结匿名化数据版本、人工标签与审核者，留至少一部分盲测集，并按复杂度/语言/附件/销售资历分组。

失败归因先看样例而不是立即换模型：自然语言单位落在 `normalization_or_unit_parsing`；候选术语和字段写法落在 `semantic_or_coverage`；附件依赖需记输入覆盖缺口；Schema/证据错为数据契约失败。字段标签和业务语义有争议时由销售与陈工回读，不能只调 Prompt 把分数调高。
