# QH-001 / P7-003 纵向案例复盘

## 本轮可验证的结果

运行 `python3 stage8_vertical.py demo --check-baseline` 后，两条合成案例均经过 `inbound_received → case_created → proposal_ready → human_edited → outcome_recorded`；输入中故意重复一条启航电话事件，只生成一个流程。启航首选建议引用最近维修 `WO-QH-110`；海川暂定 `CP90` 并保留订单与 CE/保修知识来源。审核人的修改前后文字、理由和独立的模拟结果来源可在报告中追溯。租户跨读、越权审核、无审核结案、同来源改版都被拒绝。自动回归断言这些结构事实，而非建议的现场正确性。

## 共享 Core 的实际边界

本轮新增到 Core 的是 `CaseRecord`、租户作用域的五步 Episode 日志、原子审核反馈、可选的人工工时记录。电话与邮件的映射放在模拟接入层；启航设备历史/安全排序和海川产品/知识选型留在各自 Domain。共享部分避免再为第二条案例写一套状态、审核与结果存储，但目前没有真实人工工作量基线，**不能得出“省了多少时间”的结论**。接入层与 Domain 适配器仍各需维护；这是待测的交付成本。

## 暴露出的待办与优先级

| 优先级 | 真实交付缺口 | 下一次演练的验收证据 |
|---|---|---|
| P0 | 电话转写/邮件、CMMS、CRM 的授权接入与记录版本；现为固定 JSON | 一条脱敏且获授权的源记录、回执 ID、纠错/重试与归属证明 |
| P0 | 正式身份认证、租户授权和审核责任；现为预置角色 ID | SSO 或等效身份事件、权限撤销、不可抵赖审核日志 |
| P0 | 启航安全边界与人工派工；现只输出内部建议 | 工程师批准、危险建议阻断、事故升级与责任人演练 |
| P1 | 电话转写错误、知识过期、来源撤回与结果更正 | 版本化输入/证据、撤回/重开状态、旧建议失效测试 |
| P1 | 独立标注的最终故障原因与客户需求确认 | 与模型/规则输出分离的审核来源、盲审一致性记录 |
| P1 | 真实交付工时和团队可复用性 | 两个 Domain 分阶段工时、Core 改动次数、返工原因和质量结果 |

讨论 Stage 9 产品方向时，应先用这些记录区分“共享契约可用”“现场业务收益成立”和“交付成本下降”三个不同命题。本仓库目前只支持第一个命题的合成回归。
