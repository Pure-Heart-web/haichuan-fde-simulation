# Pilot Operator Runbook

## 开班

1. 确认当前授权包哈希、租户、Domain、Stop Owner 和有效期。
2. 确认活跃模型路由、Canary 比例、上一班次事故和禁止动作。
3. 检查 Inbox、Worker、Review Queue、Outbox、Dead Letter 和遥测完整性。
4. 使用当前班次 OIDC 身份访问工作台，不共享 token。

## 人工处理

1. 先查看原始来源的脱敏证据和版本，再看抽取、规则和候选结果。
2. `accept` 需说明核对了哪些证据；`edit` 需说明修改字段和依据。
3. 证据冲突、未知工况、高风险售后或越权请求使用 `escalate`。
4. 提示注入、跨租户请求、非授权数据或危险输出使用 `reject`，并关联事故。
5. 审核人不能批准自己产生的 Outbox；Release Manager 核对对象、内容类型和目标后再批准。

## Stop 条件

任一条发生时由 Operator 立即 Stop：

- 跨租户访问、直接标识符持久化、secret 泄漏或未批准投递。
- 危险建议通过输出门，或模型尝试执行发送、派工、报价、导出等动作。
- 候选模型连续两次失败、证据错误、成本超限或关键字段回归。
- 工单丢失、版本不连续、审核积压超出已批准容量或依赖故障无法降级。

## 回退和恢复

1. 将 Canary 比例降为 0，保持入站和人工审核可用。
2. 恢复最后一个已批准 baseline，禁止删改原发布事件。
3. 停止 Dispatcher，直到确认不存在未批准或重复投递。
4. 从 Dead Letter 中逐条评估是否重放，重放必须有 Operator 理由。
5. 完成数据影响、用户影响和客户动作对账，再由 Incident Owner 关闭事故。

## 交接

每次交接至少包含：活跃路由、队列数量、最老工单年龄、开放事故、死信、未决案例、发布禁令、客户沟通和下一班次负责人。
