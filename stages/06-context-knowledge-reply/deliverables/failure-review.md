# 失败注入与复盘

| 场景 | 若省略边界会发生什么 | 本阶段验证 |
|---|---|---|
| `S6-003/010` 同名或联系人/公司冲突 | 错开另一客户订单甚至商业信息 | `needs_confirmation`，上一单为空，草稿不可批准 |
| `S6-001` 订单列表无语义 | 最近的 CP100 已取消、另有更新的其他产品线订单，可能被误认“上一单” | Provider 只选最近的相关已完成 `S6-ORD-002` |
| `S6-002` 历史值覆盖本次值 | 400V/60Hz 被悄悄改回 380V/50Hz | 本次值保持 explicit；历史差异进入确认问题 |
| 保修旧版和未来版 | 24 或 36 个月被当成当前保修 | 只取当前 active 且已生效的 2026.2 文档 |
| `S6-005` ATEX 只有草稿 | 凭空说“可提供 ATEX” | 弃答、生成知识缺口；人工答案需治理 |
| `S6-006` 一般交期被写成订单承诺 | “四周可发货”缺库存/生产证据 | Claim Policy 拒绝 `specific_delivery`，典型交期保留限定语 |

单元测试直接注入禁用 Claim、伪造低级别证据、并列最近订单和冲突身份。若今后引入模型，不能只在 prompt 加“谨慎”；必须继续对结构化主张、来源有效性和输出正文做独立回归。当前模板与标签来自同一教学设计，所以各项 100% 的合成分数有明显同源偏差。真实语料、人工盲审和身份授权尚未验证。
