# Stage 6 架构决策记录（教学模拟）

**ADR-006 · Context 与 Knowledge 分离。** 具体客户的订单从客户 ID 限定的业务表查询；一般保修、认证和安装说明从有版本的知识文档检索。全文相似度不能替代身份关联或订单排序。

**ADR-007 · 历史值不得静默覆盖当前事实。** 只有显式引用上一单才取历史；`ResolvedField` 区分 `explicit_current` 与 `historical_reference`，来源保留 WorkItem/Order ID。草稿把历史电气配置表述为待确认信息。

**ADR-008 · 高风险 Claim 要证据和审批。** 结构化 Claim Policy 在正文组装前运行。保修、认证和历史订单要有有效来源；典型交期带限定语；最终型号要批准记录；价格、折扣、具体交货和合同承诺在 V1 不生成。

**ADR-009 · 无证据时弃答。** draft、superseded、未生效、地区或 SKU 不适用的文档均不作为答案。ATEX 无 active 文档时只说需要核实，并创建知识缺口。人工确认答案需进入治理，不自动变成正式知识。

**ADR-010 · 内容计划与风格分离。** 内容计划先确定必须说、不能说、要追问什么；风格配置只处理称呼、语气和段落。当前使用可重复的确定性模板，以便直接检查每个 Claim 的来源；以后更换 LLM 仍须通过同一政策和评估边界。
