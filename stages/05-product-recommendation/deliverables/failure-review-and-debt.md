# 失败复盘与技术债登记

当前合成评估没有明确禁用 SKU 暴露，也没有漏掉已标注的候选；这只说明这 24 条教学案例。两条误升级说明当前排序代理的代价：`MATCH-004` 的 CP100 工作点接近模拟范围一端，`MATCH-021` 的 CP80 靠近扬程下限；系统把范围边缘视作“工程师应介入”，但教学标签认为销售可处理。当前保守策略保留，不通过调低警告来粉饰合成指标。让陈工以真实产品曲线和签核版本审查边界，再决定阈值与销售授权范围。

| 技术债 | 当前短期处理 | 长期触发条件 / 所需证据 |
|---|---|---|
| 无真实性能曲线 | 只输出区间代理和未验证警告 | 获取曲线、工况定义及工程师签核后实现曲线计算 |
| 误升级 2/8 | 在报告与 UI 显示警告，保留人工判断 | 真实负例足够后共同调整阈值；检查升级漏召回 |
| 数据源歧义 | CPX-UNK 隔离；CP90 以 Stage 3 技术源为准 | 客户出具正式主数据 owner、版本和变更流程 |
| 产品线窄、无非标 | 泛称 pump 和非标准工况升级 | 扩线前补数据契约与每线规则回归 |
| 未接价格/库存/CRM | 不参与排序、不输出商业承诺 | 权限、时效、引用与审计均就绪后单独集成 |
| 人工审核身份简单 | 本地角色字段做流程演练 | 真实环境需登录、权限、操作者身份与事件签名 |

新增失败时，先标为数据缺口、硬筛、规则、排序、升级或 UI 操作，再记录案例 ID、版本、期望与实际；修复后新增独立回归案例，不能仅修改原标签让指标变好。
